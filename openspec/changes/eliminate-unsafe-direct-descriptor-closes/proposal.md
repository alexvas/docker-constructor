## Why

Several descriptor-owning paths still use bare `finally: os.close(fd)`, multi-descriptor loops that stop after the first close failure, or manual parent/child handoffs that can mask an active operation failure, skip independent releases, retry an ambiguously failed close, or leak an already-open child. The new lightweight `docker.filesystem` ownership and cleanup primitives now provide a common way to remove these defects without coupling leaf domains to `docker.transactions` or turning the foundation into a general VFS.

The generic process owner now exists; this change also establishes its domain-neutral launch-configured stop-policy API so later execution wrappers can request staged stopping without overriding resource coordination.

## Approved Phase 7 Delivery Boundary

The user delegated native local-file factory stream ownership, including the five identified readers and replacement of the staged `_FileRelease` proxy, to [own-local-file-stream-lifecycles](../own-local-file-stream-lifecycles/proposal.md). This is independent of the earlier [HTTP/probe lifecycle delegation](../own-http-response-and-probe-server-lifecycles/proposal.md). Neither delegated family's resolution is a prerequisite for this change's Phase 7 acceptance.

Phase 7 still scans the complete production tree, reports delegated origins separately and proves all remaining in-scope raw-fd/directory/`mkstemp`/`fdopen`/subprocess lifecycles. No whole module or runtime ownership rule is exempted. Delegation does not classify the staged proxy as a valid owner, approve a new stream API here, or complete tasks 7.1–7.10; their current convergence, ledger and `verification.md` obligations remain. The lifecycle guarantees below remain required, with delivery for the explicitly delegated families owned by their separate changes.

## What Changes

- Inventory every direct and implicit descriptor lifecycle across the production tree—including `os.fdopen(..., closefd=True)` adoption and raw descriptors returned by `tempfile.mkstemp()`—migrate every in-scope consumer-owned release to an owned lifecycle or protected cleanup, recording explicitly delegated families separately, and bind every retained direct close to exactly one permitted classification: low-level POSIX primitive, shared-owner internal release, or verified ownership handoff.
- Replace single-descriptor consumer lifecycles in npm lockfile writing/tree hashing, runtime artifact verification, private build-context writing, snapshot destination copy, artifact-cache temporary creation, and validated project state with `OwnedDescriptor`; active-primary cleanup additionally uses shared cleanup precedence while success-path release remains terminal and at-most-once through the owner.
- Package `docker/filesystem/` into `/usr/local/lib/pi-cli/docker/filesystem/` in the image so the migrated runtime installer can resolve its lightweight lifecycle imports without relying on the source repository.
- Refactor build-cache multi-descriptor release so every descriptor has an `OwnedDescriptor` lifecycle and one aggregate `CleanupFailures` attempts every independent release even when another close fails.
- Replace unsafe manual directory parent/child handoff and `_bootstrap_constructor_project_lock_parent()` in `docker/versioning/build_cache.py` with `DirectoryDescriptor`/`OwnedDescriptor` lifecycle where the existing foundation contract is sufficient; retain build-cache path derivation, recursion, lock policy, cache identity, durability, and domain errors locally.
- Preserve direct close only inside low-level POSIX adapters, inside `OwnedDescriptor.close()` (or an equivalent shared-owner implementation) after ownership is terminal, and as an ownership-handoff operation whose parent is terminal and whose child is already tracked; consumer success-path and lifecycle close operations delegate to that shared owner even when only one descriptor is involved.
- Add production-tree symbol-origin and fd-ledger gates that resolve direct and aliased POSIX close callables, arbitrarily named injected descriptor backends, aliased `os.fdopen`, and aliased `tempfile.mkstemp`; reject unauthorized direct release, consumer `fdopen(closefd=True)`, `fdopen(closefd=False)` without a shared owner, and unadopted factory fds, and prove no descriptor is leaked, retried, skipped, implicitly released, or hidden by renaming.
- Restore prevalidated adoption in the bounded `docker.filesystem.streams.OwnedStream`: rejected labels/interfaces and synchronization-construction failures leave caller-owned streams untouched. Preserve synchronized terminal at-most-once release; do not independently own or close a stream's `fileno()`.
- Introduce reusable `OwnedProcess` in `docker.process` to own launch, captured stdout/stderr through one `OwnedStream` each, internally controlled cancellation-aware readers, and coordinated shutdown. Prepare fallible ownership/synchronization and cleanup-continuation state before launch; protect every post-launch failure without caller-composed preparation/join/reap helpers or consumer-close fallbacks.
- Fully migrate the generic process API to immutable value results: `FailureInfo(error: BaseException, kind: FailureKind, phase: FailurePhase, stream: ProcessStream | None = None)`, `ActionResult(done, cleanup_complete, failures: tuple[FailureInfo, ...] = ())`, `LifecycleResult(complete, failures: tuple[FailureInfo, ...] = ())` and `ProcessResult(stdout, stderr, returncode, timed_out, lifecycle, stream_outcomes=())`. Replace generic CleanupResult with LifecycleResult. LifecycleResult.failures is the single aggregate failure sequence, with selected authority first, preserving exact error objects and shared precedence; ActionResult is observation transport from ManagedAction.observe(), not a nested duplicate in the final result. No parallel .error/.failure_info/error_kind/reader_failure_stream fields, raw-exception failure tuples, legacy modes or inference shims. FailureKind remains ORDINARY/UNEXPECTED/INTERRUPTION and FailurePhase remains SETUP/READ/JOIN/RELEASE/WAIT/ACTION/CALLBACK/REPORTER/COORDINATION. Preserve helper kind while rebasing parent context to ACTION/None. All producers, consumers, fixtures, examples and API assertions migrate together.
- Return ProcessResult for ordinary collection failures and unexpected defects, with bounded output, known returncode and immutable lifecycle/outcomes. Remove error.process_result entirely: no result attachment to exceptions, generic interruption snapshot or new owner.result property. Control-flow BaseException interruptions still propagate with exact first-interruption identity after bounded independent cleanup; InterruptedError remains subject to the operation's ordinary-error policy. Preserve domain retained_capture for CLI interruption diagnostics and retained cleanup observations. Before a usable prepared owner exists, launch validation/preparation may raise; once it exists, ordinary launch/setup failures return that same failed owner and its sole collection returns the value result, without fabricated children or streams. Control flow during launch propagates after protected cleanup, without promising a returned owner or output snapshot.
- Permit exactly one collection attempt per OwnedProcess: either capture() or stream(callback, *, on_stream_end=None). A second or racing collection raises a usage error, including after failure or interruption, with no replay, callback registration or cleanup restart. Retain typed ProcessStream chunks, independent EOF/READ_FAILED/ABORTED outcomes, prompt once-only terminal notifications for the sole stream invocation and pre-registration completion races. Late cleanup is observed only through cleanup_status/wait_cleanup, not another collection.
- Replace ProcessResult.callback_errors with a prevalidated optional launch reporter. Preserve prompt outside-lock reporting, domain masking, fixed-safe default and independent nonrecursive fallback, ordinary reporting isolation and control-flow propagation. No callback-error store, late subscription or automatic callback after delivery.
- Distinguish completed cleanup from `shutdown_incomplete`. Bound caller waiting, retain ownership of resources still used by readers, finish safe release after those readers stop, and expose bounded waiting and retained cleanup outcomes. Late cleanup failures do not retroactively replace an already-delivered operation result.
- Add a narrow stop-policy contract selected and prepared at `OwnedProcess.launch(...)`, shared by explicit shutdown, deadline, context exit, reader failure, and setup failure. Keep local waiting/reaping, reader-stop barriers, release, precedence and publication in the existing coordinator; do not delegate the whole shutdown or expose raw process/pipe control. Preserve the default local-process behavior.
- Supply generic bounded request/observation, optional escalation/finalization and managed-action result contracts, configurable phase caps plus reserved local cleanup inside one total deadline, and a bounded drain-before-reader-cancellation mode. Verify them with domain-neutral fake policies and real local subprocesses. Generic completion covers owned local resources, not externally controlled work.
- Migrate the existing streaming/captured npm clients through compatibility adapters without introducing a Docker wrapper or changing container-stop behavior. Preserve characterized terminate-CLI/remove/reap order, existing removal/staging policy, output/redaction and total bounds using coordinator-owned local actions and managed domain actions; no independent raw process/pipe control or duplicated lifecycle machinery.
- Require deterministic npm secondary process-cleanup note prefixes from FailureInfo only: `{subject} {operation} failed`, where stream STDOUT/STDERR/None maps to stdout/stderr/process and phase SETUP/READ/JOIN/RELEASE/WAIT/ACTION/CALLBACK/REPORTER/COORDINATION maps to setup/read/join/release/wait/action/callback/reporter/coordination. Replace the previously approved single `stream cleanup failed` prefix; do not infer legacy source labels from timeout, exception type/text, traceback or private state. Kind controls precedence, not wording; helper handoff to ACTION/None produces `process action failed`. This wording-only exception preserves primary types/messages, exact authority, domain fields, retained failures, sanitization, output, cleanup behavior and the existing number of diagnostics. Error details remain separately bounded and secret/URL-sanitized; no unbounded event/ownership log or new callback-error retention.
- Keep Docker commands/identity/status interpretation, npm errors, redaction, publication, and staging policy outside `docker.process`. Do not introduce process-tree/group management, per-PID container control, stdin, PTY, arbitrary external reader ownership, or runtime-installer adoption.
- Extend production-tree origin tracking to aliased subprocess factories, `PIPE` arguments, returned stream attributes, and stream-close callables; classify their underlying release only inside the terminal shared owner, not as a non-descriptor exemption.
- Establish durable developer rules in `docs/filesystem-lifecycle.md`, root `AGENTS.md`, and OpenSpec project context, with README links and assembler shutdown documentation, so new descriptor-owning code selects a filesystem wrapper and verifies ownership instead of inventing another release state machine.
- Preserve existing consumer public APIs, error types/messages, persistent paths, modes, hashes, cache identities, publication order, lock semantics, and durability behavior. Authorized corrections are the sole runtime-artifact close `OSError` to controlled `InstallError` mapping, prevalidated stream adoption, terminal at-most-once stream release, shared cleanup precedence, explicit reporting/retention of incomplete process cleanup and the additive generic policy API. Existing normal/cancelled consumer output, input parameters, domain result fields and Docker cleanup order remain compatible in this change. The generic process API explicitly authorizes the orthogonal value-result migration above, ordinary/unexpected failure return rather than raise from collection, single-use collection, removal of error.process_result and redundant error/metadata fields, and complete producer/fixture/docs migration. Domain result fields and capture input signature remain unchanged; repeated collection/subscription is intentionally removed. The explicitly authorized captured-adapter return-contract change is `run_captured(...) -> tuple[OwnedProcess | None, LifecycleOutcome]`, replacing the raw `Popen` in the first tuple element while retaining `LifecycleOutcome` as the delivered result snapshot and the owner as cleanup observation access. Captured test factories must provide both requested streams; missing stdout/stderr is a malformed factory result requiring controlled failure and safe bounded cleanup, not legacy successful execution with empty output. Keep generic missing-stream rejection unchanged. Introducing cooperative Docker behavior is out of scope. The only public filesystem addition remains bounded `OwnedStream`; reusable process coordination is a separate `docker.process` API. Preserve supported subprocess output, redaction, deadline bounds, and controlled error reporting.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `durable-filesystem-transactions`: Extend the existing shared resource-cleanup boundary with prevalidated stream transfer and reusable process-lifecycle guarantees: failure-safe launch, launch-configured narrow stop policies, policy-defined stage caps, optional bounded draining and fallback, exhaustive shared-precedence shutdown, safe retained ownership during incomplete cleanup, and observable eventual cleanup outcomes. Preserve synchronized terminal stream release and enforceable developer guidance.
- `locked-npm-environment-assembly`: Require streaming execution and captured cleanup clients to use unified process ownership while preserving npm domain policy, output identity, sanitized diagnostics, bounded shutdown, reader safety, the existing domain cleanup order, and controlled reporting of incomplete local cleanup.
- `docker-runtime`: Require mounted runtime-artifact descriptor release not to mask validation, read, or integrity failures and to remain at-most-once.
- `build-artifact-materialization`: Require build-context, artifact-cache, build-cache, snapshot, and project-state descriptor lifecycles to avoid skipped cleanup, unsafe handoff, repeated close, and child leaks without changing domain protocols.
