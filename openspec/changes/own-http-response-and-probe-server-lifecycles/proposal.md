# Proposal

## Why

Phase 7 preflight of `eliminate-unsafe-direct-descriptor-closes` found uncharacterized network resources: buffered and streaming HTTP responses, error-response bodies, and the gateway probe's listening server. The preflight demonstrated that the buffered transport returned an `HTTPError` body without releasing it; the other paths also needed explicit ownership and failure characterization rather than exemptions based on stdlib names or native context managers. The immediate minimal repairs below are now implemented; this change retains the broader lifecycle guarantees as remaining work.

## Delivered Minimal Baseline

- Buffered metadata and streaming acquisition HTTPError paths now release the error response through `OwnedStream`; successful responses still use their existing native context managers. Buffered HTTPError-handler sole close errors currently propagate rather than use the planned uniform 503 mapping.
- The artifact consumer explicitly finalizes closeable chunk iterators, including externally retained generators after processing failure, using shared cleanup precedence; compatible plain iterators remain supported.
- Probe startup prepares a listener adapter and `OwnedStream` before server acquisition and cleans failed startup without shutdown/join of a never-started thread. Sequential stop detaches references before shared-accumulator shutdown, release and started-thread join, preventing ordinary repeated/reentrant close; a second sequential active start is rejected.
- Added 29 targeted regressions, including operation-plus-close/interruption cases and real listener/worker release. Regenerated the existing source-hash/dependency inventory without weakening its equality assertion.
- Minimal-patch acceptance: **7862 passed, 13 skipped, 11 warnings**, typecheck, diff check and both strict change validations passed. Complete logs, intermediate failures and scope limits are recorded in [minimal-fix-verification.md](minimal-fix-verification.md). This does not claim full change acceptance or original Phase 7 completion.

Preparation before HTTP acquisition, ordinary-response migration, isolated one-shot probe startup/stop, uniform error mapping and expanded ownership enforcement remain pending. The probe is a temporary child process, not a general server: one diagnostic controller owns one instance for the entire gateway-candidate sequence. The parent requests immediate SIGKILL and makes a bounded best-effort attempt to reap/settle resources; failure to confirm cleanup warns but does not invalidate completed gateway checks. The generic owner must still report incomplete cleanup honestly. Socket inactivity limits protect against stalled clients, and an internal finite-lifetime watchdog remains backup protection. Graceful request draining, concurrent probe lifecycle calls, restart and a new probe-specific incomplete-cleanup observation protocol are outside its contract. The completed baseline is tracked separately at the beginning of `tasks.md`; later tasks extend and verify it rather than discard or reimplement it.

## What Changes

The following describes the full target beyond the delivered minimal baseline; partial overlap is not evidence that the broader tasks are complete.

- Give successful and error HTTP responses one prepared filesystem stream owner before fallible use, including exceptions raised by `urlopen`; preserve response bytes, status, headers, request configuration and existing error boundaries.
- Release streaming responses on EOF, read failure, interruption and explicit iterator termination. Finalize owned download iterators deterministically when the artifact consumer fails, without depending on garbage collection or requiring injected plain iterators to implement a new API.
- Run one temporary probe child process for the whole gateway-candidate sequence, with readiness/error reporting before use. Use one-second listener/idle waits and fixed three-second accepted-connection read/write inactivity timeouts. This intentional hygiene restriction is independent of, and may be shorter than, the configurable 1–300-second client probe_timeout; it can close a stalled connection earlier but is not a total candidate deadline and does not change client retry behavior. After checks, failure or interruption, request immediate SIGKILL through `OwnedProcess` without preceding SIGTERM/grace. Attempt reap and parent-side cleanup within the existing five-second observation budget. Ordinary cleanup failure or incompleteness must warn without discarding completed checks or replacing the original diagnosis error; unexpected defects and interruptions retain shared precedence. Never label incomplete owner cleanup complete.
- Add a private synchronous warning adapter in networking using the named logger `docker.networking.probe_cleanup`, one fixed warning and at most one controlling-thread attempt per lifecycle. Do not change public signatures/DTOs, configure handlers/root logging or add a reporting queue/thread. Reporting `Exception` failures are best effort; control-flow interruptions still propagate. Warning size/attempt count are bounded, not arbitrary handler runtime: the five-second budget covers cleanup observation only. Background collectors/continuations never invoke this adapter or present diagnostics.
- Keep the child's independent finite-lifetime watchdog. Early child exit, invalid readiness or watchdog expiry during checks remains a diagnosis failure, unlike an unconfirmed teardown after finished checks. Retain the same generic cleanup continuation when resources remain unsettled; no indefinite foreground wait or extra probe-specific cleanup coordinator is required.
- Extend `OwnedProcess`'s launch-selected local stop policy with an opt-in immediate-kill mode; preserve terminate-then-kill as the default for every existing consumer. Reuse its process/pipe ownership, budgets, failure classification and incomplete-cleanup continuation instead of adding a second subprocess coordinator.
- Keep HTTP/server/readiness/watchdog policy in networking and its private worker. Reuse `OwnedStream` / `CleanupFailures` and `OwnedProcess`; add no public filesystem API, raw-fileno owner or generic network framework. Forced child exit relies on kernel descriptor reclamation, not Python finalizers or graceful request completion.
- Extend lifecycle enforcement to implicit HTTP-response acquisition and `server_close()` aliases, with concrete adapter/ownership proofs and negative fixtures, not a fourth direct-close category.
- Characterize all new families RED before migration, verify compatibility and real loopback resource release, and produce executable inventory/evidence for the original change's later Phase 7 re-audit.

## Capabilities

### New Capabilities

- `http-transport-lifecycle`: Explicit successful/error response ownership and deterministic streamed-response finalization across metadata and artifact HTTP consumers.

### Modified Capabilities

- `build-networking`: Isolated temporary probe process, socket inactivity limits, bounded readiness, best-effort SIGKILL/reap with nonfatal cleanup warning, backup self-expiry and preservation of gateway diagnosis and existing process-consumer defaults.

## Impact

Production scope is `docker/versioning/transports.py::build_transports._ProductionHttp.request`, `docker/versioning/artifact_cache.py::HttpStreamingTransport.fetch_chunks` and its artifact-download consumer, `docker/networking.py::HostProbeServer` plus the diagnosis cleanup boundary, a private probe-worker entry module, and the explicit local-stop-mode extension in `docker/process.py`. Process policy API changes are additive and opt-in; existing callers retain their default signal sequence. The parent must not signal/reap borrowed children or read/release captured pipes independently. Preserve `_host_probe_factory` and `GatewayDiagnosis`: use an optional private health-check method with absent meaning unknown so existing injected probes providing only port/token/start/stop remain valid. Phase 3 alone replaces the historical thread-specific probe regressions with equivalent process-model proofs, recorded in verification evidence. Small private domain adapters may prepare release capacity before acquisition; the filesystem foundation's public surface remains unchanged.

Implementation also refreshes the existing generated source-hashed architecture inventory as derived evidence when these source edits make it stale, preserving its equality gate and recording why it changed; that refresh is not Phase 7 acceptance. Tests cover transport results, download publication/error boundaries, networking diagnosis, injected lifecycle faults and loopback fd/port safety. Architecture/documentation enforcement stays in `tests/enforcement/`. Metadata/artifact request, cache, auth, retry, timeout, redaction, integrity/publication and Docker gateway-selection policies are not redesigned. Client probe_timeout remains 1–300 seconds with unchanged forwarding to the container fetch; the explicitly added fixed server-side inactivity limit is an accepted slow-client compatibility restriction, not a claim that every previous slow request still succeeds. Pending metadata-revalidation work must retain these lifecycle guarantees without being implemented here.

This change builds on the implemented filesystem ownership/cleanup baseline from `eliminate-unsafe-direct-descriptor-closes`, not on that change's unfinished Phase 7. Creating this plan neither completes nor narrows its tasks and does not resolve its preflight blocker. After the remaining improvements are implemented and verified, the original complete-tree audit must be rerun and its evidence regenerated. The minimal patch already refreshed its derived source-hash/dependency inventory; original specifications, task states and historical acceptance remain unchanged.
